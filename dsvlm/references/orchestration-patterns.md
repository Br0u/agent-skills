## 0. 通用编排顺序

新算法优先按三层拆：

1. 可见锚点：人、车、手、门、头盔、刀、棍、纸张、水域、护栏、横幅等。非内置目标优先用英文 `目标理解 / 多模态目标理解`。
2. 语义复核：动作、关系、状态、意图外显证据。细动作或高误报交互可用 `内容理解 / 正向思维1` 加 `深度内容理解 / 正向深度思维1` 双校验。
3. 窄反向排除：默认放在主证据之后；高误报场景可前置为过滤门槛，但只排除明确正常或不可判定画面。

不要把截图里的阈值、延伸比例、排序、门户开关照抄成固定规则。它们是参数，不是业务判断。

## 1. 简单目标

只找明确物体时，优先只用 `目标理解`，不要额外加语义行。内置目标可用 `通用目标理解`；非内置或截图里的开放词目标优先用英文 `多模态目标理解`。

```text
算法: 寻找电动车
思维条件1: 目标理解 / 通用目标理解 / 摩托车/电动车 / 大于 / 0
```

```text
思维条件1: 目标理解 / 多模态目标理解 / car door / 大于 / 0 / 阈值 60
```

## 2. 目标加属性

大类用 `目标理解`，颜色、状态、材质、姿态等属性用内容/深度内容理解补充。先锚定英文目标，再写属性或关系，不要只写抽象中文词。

```text
思维条件1: 目标理解 / 通用目标理解 / 汽车 / 大于 / 0
思维条件2: 深度内容理解 / 正向深度思维1 / 如果车是白色的就预警
思维条件3: 内容理解 / 反向思维1 / 不是白色车子不要预警
思维条件4: 内容理解 / 反向思维1 / 深色车子不要预警
```

## 3. 多目标关系或动作

不要只写 `人 AND 电动车`，这只能说明两者同时出现，不能说明人在骑车。必须加关系行。

```text
思维条件1: 目标理解 / 通用目标理解 / 人 / 大于 / 0
思维条件2: 目标理解 / 通用目标理解 / 摩托车/电动车 / 大于 / 0
思维条件3: 内容理解 / 正向思维1 / 如果这个人正在骑电动车，则预警
```

用于：人骑车、人拿物、人靠近车、人操作设备、人进入区域等。

细动作或高误报交互不要只停在目标锚点。可先锚定 `person / hand / car door / helmet / stick` 等目标，再用普通正向思维确认动作，用正向深度思维复核细节和关系。

```text
思维条件1: 目标理解 / 多模态目标理解 / car door / 大于 / 0 / 阈值 60
思维条件2: 目标理解 / 多模态目标理解 / hand / 大于 / 0 / 阈值 50
思维条件3: 内容理解 / 正向思维1 / 图中是否存在手拉车门把手的行为
思维条件4: 深度内容理解 / 正向深度思维1 / 图中是否明确存在伸手拉车门把手的行为
```

## 3a. 目标安装方式或摆放状态

识别标识牌、标签、设备附件、门牌等物体时，先用 `目标理解` 找到物体，再用内容理解判断它和载体的关系。不要只写“有 tag”，那只能说明目标出现，不能说明它是挂着、贴着、放着还是脱落。

```text
思维条件1: 目标理解 / 多模态目标理解 / tag / 大于 / 0 / 阈值 30
思维条件2: 内容理解 / 正向思维1 / 图中的 tag 是挂在柜子上的标示牌
思维条件3: 内容理解 / 正向思维1 / 图中的 tag 不是粘贴在柜子上的
```

物体很小、需要围绕目标看安装状态时，必须保留 `目标理解` 才会给物体套框；需要细节判断时再配合 `深度解析模式` 和较小延伸比例。固定设备区域内检测时开启 `启用区域框`。

## 4. 工具型动作

钓鱼、施工、清扫、操作设备等场景，核心是“人正在使用工具做动作”。

```text
思维条件1: 目标理解 / 通用目标理解 / 人 / 大于 / 0
思维条件2: 内容理解 / 正向思维1 / 图中是否有人使用鱼竿钓鱼
```

工具很小或不在内置目标里时，不要强行用通用目标理解找工具；如果工具在截图中清晰可见，优先用英文多模态目标锚定，再用动作语义复核。

## 5. 抽象动作拆解

`贴广告`、`抽烟`、`打架`、`违规作业` 等抽象行为，要拆成摄像头可见证据。

证据链：

1. 行为主体：谁可见，例如人员、工人、路人。
2. 物品/工具：拿着或使用了什么，例如香烟、打火机、纸张、工具。
3. 动作/接触：可见动作，例如靠近嘴部、按压墙面、击打、攀爬。
4. 目标/位置：动作发生在哪里，例如墙面、电线杆、玻璃、门、禁区。
5. 结果状态：发生什么变化，例如烟雾、海报留在墙面、物品损坏。
6. 排除项：大多数情况下只在调试误报时添加，不要作为初始配置的默认组成部分；高误报场景可前置窄排除，但不能写成会压掉正例的宽泛正常状态。

不要只写 `贴广告`、`违规`、`异常` 这类抽象标签。

## 6. 弱可见结果证据和简化优先

不要过度依赖小物体、新增物体、表面变化或细微状态变化。侧视、远景、低清、逆光、模糊、遮挡时，这类证据不稳。

```text
优先: 行为主体 + 物品/工具 + 动作/接触 + 动作完成证据
避免: 行为主体 + 物品/工具 + 动作/接触 + 很小或不清晰的最终结果
```

替代思路：

```text
新增物体清晰可见 -> 使用新增物体结果
新增物体不稳定 -> 使用手部离开目标表面、身体离开位置、工具离开目标、动作完成姿态
细小状态变化不稳定 -> 使用导致该变化的更大、更可见动作
```

复杂动作不一定条件越多越准。对大模型语义组件，过多细节会变成硬门槛，导致低清、遮挡、角度变化时漏报。优先用 2-4 条稳定、宽泛、摄像头可见的主证据跑通。

基础格式：

```text
思维条件1: 内容理解 / 正向思维1 / 人员正在操作与该行为相关的物品或工具
思维条件2: 内容理解 / 正向思维1 / 人员在目标位置附近做出该行为的关键接触动作
思维条件3: 内容理解 / 正向思维1 / 人员完成该动作后，手部、工具或身体离开目标位置
```

debug 误报时再追加：

```text
思维条件4: 内容理解 / 反向思维1 / 针对实测误报类型写具体排除，例如查看、路过、清理、维修、授权操作
```

## 7. 手持小物和遮挡

抽烟、拿工具、拿东西等场景，小物体经常太小或被遮挡。先检测 `人`，再写人与手部/物品关系。

```text
思维条件1: 目标理解 / 通用目标理解 / 人 / 大于 / 0
思维条件2: 内容理解 / 正向思维1 / 行人手上拿着物品或正在操作物品
```

如果“看不到手/被遮挡”本身也应触发，要明确写成风险条件，或反向排除安全状态：

```text
思维条件3: 内容理解 / 正向思维1 / 人员手部被遮挡、不可见，且疑似正在携带或操作物品
思维条件4: 内容理解 / 反向思维1 / 双手清晰可见且未拿任何物品
```

## 8. 小物体混淆

香烟、鱼竿、手机、小工具都可能很小。用“手/嘴/工具/动作/点燃或使用状态”组合判断，并写常见误报。

```text
思维条件1: 内容理解 / 正向思维1 / 是否嘴里有烟
思维条件2: 内容理解 / 正向思维1 / 是否手中有烟
思维条件3: 内容理解 / 正向思维1 / 是否点着了
思维条件4: 内容理解 / 正向思维1 / 是否手里夹着烟
思维条件5: 内容理解 / 反向思维1 / 是否误识别为棒棒糖
```

如果这些只是同一行为的多个可见说法，优先合成一条“符合任一情况”的内容理解；不要为了枚举同义证据就加平台 OR。

## 9. 人员身份、年龄、性别、服饰

先用 `目标理解 / 人` 锚定人员，再用内容/深度内容理解判断身份特征。

身份类不要只写“指导员/老人/儿童/陪酒女”等标签，要拆成可见证据：

```text
脸
正脸
完整身体
年龄
性别
制服
袖章
反光背心
马甲
特殊服饰
```

示例：

```text
思维条件1: 目标理解 / 通用目标理解 / 人 / 大于 / 0
思维条件2: 内容理解 / 正向思维1 / 图中是否可以看到正脸
思维条件3: 内容理解 / 正向思维1 / 图中人是否为儿童
思维条件4: 内容理解 / 反向思维1 / 图中人是否为成年人
```

看不清脸、身体或服饰时，不要过度相信年龄/性别/身份判断。

## 10. 人员身份排除

识别指导员、工作人员等角色时，要排除相似职业或相似穿着。

```text
思维条件1: 目标理解 / 通用目标理解 / 人 / 大于 / 0
思维条件2: 深度内容理解 / 正向深度思维1 / 图中人是否穿着反光背心
思维条件3: 深度内容理解 / 正向深度思维1 / 图中人是否穿着马甲
思维条件4: 深度内容理解 / 反向深度思维1 / 图中人是否是送外卖或者送快递的
```

## 11. 容器状态

垃圾桶满溢、未盖盖等任务，写成“容器目标 + 状态证据 + 正常状态反向排除”。

满溢：

```text
思维条件1: 目标理解 / 多模态目标理解 / garbage bins / 大于 / 0
思维条件2: 深度内容理解 / 正向深度思维1 / 图中垃圾桶本身是否有明显的溢出
思维条件3: 深度内容理解 / 正向深度思维1 / 图中垃圾桶的垃圾堆积超出了桶的边缘
思维条件4: 深度内容理解 / 反向深度思维1 / 图中垃圾是否相对规整且明显的在垃圾桶内
```

未盖盖：

```text
思维条件1: 目标理解 / 多模态目标理解 / garbage bins / 大于 / 0
思维条件2: 深度内容理解 / 正向深度思维1 / 图中垃圾桶盖翘起、敞开、半开，桶口明显外露
思维条件3: 深度内容理解 / 反向深度思维1 / 图中垃圾桶盖完全闭合，桶口不可见
```

## 12. 缺失和未穿戴

“未戴安全帽”“未穿反光衣”等缺失类任务，本质是“有人 + 关键部位可见 + 没有合规装备”。先找主体和对应部位，再判断缺失；看不到头、看不清脸、严重遮挡时属于不可判定，不要硬判。

```text
思维条件1: 目标理解 / 多模态目标理解 / motorcyclist / 大于 / 0 / 阈值 65
思维条件2: 目标理解 / 多模态目标理解 / person / 大于 / 0 / 阈值 75
思维条件3: 目标理解 / 多模态目标理解 / helmet / 等于 / 0 / 阈值 50
思维条件4: 内容理解 / 反向思维1 / 图中是否看不到人的头
思维条件5: 内容理解 / 正向思维1 / 图中的人骑车没有戴头盔
```

## 13. 高风险行为

暴力、打架、严重攻击等高风险行为，可以用多条兼容的正向描述提高精度。

```text
思维条件1: 内容理解 / 正向思维1 / 图中是否存在严重暴力攻击行为
思维条件2: 内容理解 / 正向思维1 / 图中是否发生严重打架斗殴行为
思维条件3: 目标理解 / 通用目标理解 / 人 / 大于 / 0
思维条件4: 内容理解 / 正向思维1 / 图中是否存在明显的肢体攻击动作
```

注意：不添加逻辑行时，这些正向描述会被平台按 `AND` 组合，必须能同时成立。若只是同一行为的不同说法，合成一条内容理解；若确实是独立候选行为，才用 `逻辑理解 / 或者` 并按第 15 节完整展开分支。

高误报场景可以前置窄反向排除，例如正常交谈、搭肩、挥手、姿态放松、无肢体对抗意图；但不要把“没有明显暴力”这类宽泛否定写得过强。

## 14. 复杂场景判断

交通事故、花屏、异常画面这类全局场景，优先用内容/深度内容理解或稳定事件目标，不要强行拆成目标。整图事件一般比串行解析更适合 `深度解析模式`。

```text
思维条件1: 内容理解 / 正向思维1 / 图中主干道路是否发生了明显交通事故
思维条件2: 内容理解 / 反向思维1 / 图中主干道路未发生交通事故
思维条件3: 深度内容理解 / 正向深度思维1 / 图中主干道路是否发生了明显交通事故
思维条件4: 深度内容理解 / 反向深度思维1 / 图中主干道路未发生交通事故
思维条件5: 深度内容理解 / 反向深度思维1 / 画面存在明显彩色斑点、条纹或像素花屏现象
思维条件6: 内容理解 / 反向思维1 / 图中画面发生断层
```

误报来源如果是画质问题、花屏、断层，要单独写反向排除。

## 15. OR 分支

`逻辑理解 / 或者` 用于两个或多个完整触发路径。公共条件不要只写在 OR 前面，要在每个分支重复。

OR 适合“不同目标锚点代表同一风险”的分支枚举：

```text
paper in hand 分支 || card 分支
knife 分支 || stick 分支
truck carrying people 分支 || tricycle/bicycle carrying people 分支
fallen person 分支 || 肢体撕扯冲突分支
```

每个分支都要有自己的目标锚点和动作/状态复核，不要把 OR 当成局部连接词。

```text
思维条件1: 目标理解 / 通用目标理解 / 人 / 大于 / 0 / 阈值 50
思维条件2: 内容理解 / 正向思维1 / 图中人员靠近水域、岸边、桥边或河道边等临水危险区域
思维条件3: 内容理解 / 反向思维1 / 图中人员在平地上、护栏内、人行道或非临水区域正常行走
思维条件4: 逻辑理解 / 或者
思维条件5: 目标理解 / 通用目标理解 / 人 / 大于 / 0 / 阈值 50
思维条件6: 内容理解 / 正向思维1 / 图中人员跨坐在桥梁栏杆、护栏或边缘上，身体悬空于水体上方或部分探出护栏外
思维条件7: 内容理解 / 反向思维1 / 图中人员在平地上、护栏内、人行道或非临水区域正常行走
```

错误写法：

```text
思维条件1: 目标理解 / 通用目标理解 / 人 / 大于 / 0 / 阈值 50
思维条件2: 内容理解 / 正向思维1 / 图中人员靠近临水危险区域
思维条件3: 逻辑理解 / 或者
思维条件4: 内容理解 / 正向思维1 / 图中人员跨坐或探出护栏
思维条件5: 内容理解 / 反向思维1 / 图中人员正常行走
```

上面的错误写法等价于 `(人 AND 临水危险) || (跨坐/探出护栏 AND 正常行走排除)`，不是 `人 AND (临水危险 || 跨坐/探出护栏) AND 正常行走排除`。

## 16. 场景门槛和误报排除

临水、禁区、道路、工地等风险任务，误报经常来自“局部物体像目标场景”或“人和危险源只是同画面出现”：例如陆地栏杆像临水栏杆、远处水面和人无关、背对水面坐地休息、普通骑车人像风险人员。先补全局场景门槛，再补人员和危险源的朝向/互动关系，最后针对实测误报补反向排除。

防溺水场景要把报警条件从“人在水边”收紧到“人在水边做危险动作”。不要写很复杂的长描述，优先用“短描述 + 强判据 + 少量排除”：强判据抓攀爬、跨越、骑跨护栏、手脚搭栏杆、身体探出等危险动作；排除项只覆盖正常走路、散步、骑行、钓鱼等常见误报。

```text
思维条件1: 深度内容理解 / 正向深度思维1 / 图中是否有河流、水域、湖面、河道或明显临水环境
思维条件2: 目标理解 / 通用目标理解 / 人 / 大于 / 0 / 阈值 50
思维条件3: 内容理解 / 正向思维1 / 图中人员在桥边或河边有攀爬、跨越、骑跨护栏、手脚搭栏杆、身体探出护栏外等危险动作
思维条件4: 内容理解 / 反向思维1 / 图中人员只是正常走路、散步、骑车经过或正常钓鱼
```

需要多个独立高危分支时再用 `逻辑理解 / 或者`，并在每个分支重复场景门槛、人员目标和反向排除。不要写成“靠近水域 OR 高危动作”，否则靠近水域会变成过宽的独立报警路径。

宏观思路：

1. 先问“这个画面是不是目标场景”，不要直接从局部物体触发。
2. 再问“最强的危险动作是什么”，不要只用距离或同画面出现判断风险。
3. 临水报警优先抓攀爬、跨越、骑跨、探身、手脚搭栏杆等动作；“人在水边”只能做场景背景，不能单独做报警核心。
4. 条件描述宁可短一点，也不要把朝向、距离、姿态、意图全塞进同一条；复杂长句容易变成漏报硬门槛。
5. 误报类型明确后，写少量具体反向排除，例如正常行走、骑车经过、钓鱼；不要为了“更严谨”默认堆很多排除。
6. 有 OR 时，每个分支都重复公共场景门槛和反向排除项。

## 17. 参数和解析模式

### 解析模式

不要机械默认通用或深度：

| 任务结构 | 优先模式 |
| --- | --- |
| 简单锚点、普通物体识别 | `通用模式` |
| 整图事件、复杂语义、身份服饰、脸部表情、事故状态 | `深度解析模式` |
| 多锚点局部交互、穿戴缺失、手部动作、目标间逐步过滤 | `深度串行解析` |

两个及以上目标理解不等于必须串行。`人 + 车`、`人 + 狗` 这类整图关系，串行可能拆散关系，先考虑深度解析或通用模式加关系语义。

### 阈值和远近比

- 阈值不是固定 50。稳定大目标或误报代价高的具体目标可提高；危险事件、低清远景、小目标或漏报代价高的目标可降低，再用语义复核兜误报。
- 远近比、延伸比例只是扩展目标框上下文，不是业务条件。手部、脸部、车门、小物体可用小比例扩展；整图事件不要强依赖延伸比例。

### 区域框和门户

- 有明确目标框、需要定位告警对象时开 `启用区域框`。
- 纯整图分类、不需要框或目标框不稳定时可关。
- `添加到门户` 不默认开启；只有用户要求、重点展示类算法或需要门户侧直接查看时再开。
