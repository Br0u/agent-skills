# 编排模式

## 目录

- `1. 简单目标`
- `2. 目标加属性`
- `3. 多目标关系或动作`
- `3a. 目标安装方式或摆放状态`
- `4. 工具型动作`
- `5. 抽象动作拆解`
- `6. 弱可见结果证据和简化优先`
- `7. 手持小物和遮挡`
- `8. 小物体混淆`
- `9. 人员身份、年龄、性别、服饰`
- `10. 人员身份排除`
- `11. 容器状态`
- `12. 缺失和未穿戴`
- `13. 高风险行为`
- `14. 复杂场景判断`

## 1. 简单目标

只找明确物体时，优先只用 `目标理解`，不要额外加语义行。

```text
算法: 寻找电动车
思维条件1: 目标理解 / 通用目标理解 / 摩托车/电动车 / 大于 / 0
```

## 2. 目标加属性

大类用 `目标理解`，颜色、状态、材质、姿态等属性用内容/深度内容理解补充。

```text
思维条件1: 目标理解 / 通用目标理解 / 汽车 / 大于 / 0
思维条件2: 深度内容理解 / 正向深度思维1 / 如果车是白色的就预警
思维条件3: 内容理解 / 反向思维1 / 不是白色车子不要预警
思维条件4: 内容理解 / 反向思维1 / 深色车子不要预警
```

## 3. 多目标关系或动作

不要只写 `人 AND 电动车`，这只能说明两者同时出现，不能说明人在骑车。必须加关系行。

```text
思维条件1: 目标理解 / 通用目标理解 / 人 / 大于 / 0
思维条件2: 目标理解 / 通用目标理解 / 摩托车/电动车 / 大于 / 0
思维条件3: 内容理解 / 正向思维1 / 如果这个人正在骑电动车，则预警
```

用于：人骑车、人拿物、人靠近车、人操作设备、人进入区域等。

## 3a. 目标安装方式或摆放状态

识别标识牌、标签、设备附件、门牌等物体时，先用 `目标理解` 找到物体，再用内容理解判断它和载体的关系。不要只写“有 tag”，那只能说明目标出现，不能说明它是挂着、贴着、放着还是脱落。

```text
思维条件1: 目标理解 / 多模态目标理解 / tag / 大于 / 0 / 阈值 30
思维条件2: 内容理解 / 正向思维1 / 图中的 tag 是挂在柜子上的标示牌
思维条件3: 内容理解 / 正向思维1 / 图中的 tag 不是粘贴在柜子上的
```

物体很小、需要围绕目标看安装状态时，必须保留 `目标理解` 才会给物体套框；需要细节判断时再配合 `深度解析模式` 和较小延伸比例。固定设备区域内检测时开启 `启用区域框`。

## 4. 工具型动作

钓鱼、施工、清扫、操作设备等场景，核心是“人正在使用工具做动作”。

```text
思维条件1: 目标理解 / 通用目标理解 / 人 / 大于 / 0
思维条件2: 内容理解 / 正向思维1 / 图中是否有人使用鱼竿钓鱼
```

工具很小或不在内置目标里时，不要强行用目标理解找工具。

## 5. 抽象动作拆解

`贴广告`、`抽烟`、`打架`、`违规作业` 等抽象行为，要拆成摄像头可见证据。

证据链：

1. 行为主体：谁可见，例如人员、工人、路人。
2. 物品/工具：拿着或使用了什么，例如香烟、打火机、纸张、工具。
3. 动作/接触：可见动作，例如靠近嘴部、按压墙面、击打、攀爬。
4. 目标/位置：动作发生在哪里，例如墙面、电线杆、玻璃、门、禁区。
5. 结果状态：发生什么变化，例如烟雾、海报留在墙面、物品损坏。
6. 排除项：大多数情况下只在调试误报时添加，不要作为初始配置的默认组成部分。

不要只写 `贴广告`、`违规`、`异常` 这类抽象标签。

## 6. 弱可见结果证据和简化优先

不要过度依赖小物体、新增物体、表面变化或细微状态变化。侧视、远景、低清、逆光、模糊、遮挡时，这类证据不稳。

```text
优先: 行为主体 + 物品/工具 + 动作/接触 + 动作完成证据
避免: 行为主体 + 物品/工具 + 动作/接触 + 很小或不清晰的最终结果
```

替代思路：

```text
新增物体清晰可见 -> 使用新增物体结果
新增物体不稳定 -> 使用手部离开目标表面、身体离开位置、工具离开目标、动作完成姿态
细小状态变化不稳定 -> 使用导致该变化的更大、更可见动作
```

复杂动作不一定条件越多越准。对大模型语义组件，过多细节会变成硬门槛，导致低清、遮挡、角度变化时漏报。优先用 2-4 条稳定、宽泛、摄像头可见的主证据跑通。

基础格式：

```text
思维条件1: 内容理解 / 正向思维1 / 人员正在操作与该行为相关的物品或工具
思维条件2: 内容理解 / 正向思维1 / 人员在目标位置附近做出该行为的关键接触动作
思维条件3: 内容理解 / 正向思维1 / 人员完成该动作后，手部、工具或身体离开目标位置
```

debug 误报时再追加：

```text
思维条件4: 内容理解 / 反向思维1 / 针对实测误报类型写具体排除，例如查看、路过、清理、维修、授权操作
```

## 7. 手持小物和遮挡

抽烟、拿工具、拿东西等场景，小物体经常太小或被遮挡。先检测 `人`，再写人与手部/物品关系。

```text
思维条件1: 目标理解 / 通用目标理解 / 人 / 大于 / 0
思维条件2: 内容理解 / 正向思维1 / 行人手上拿着物品或正在操作物品
```

如果“看不到手/被遮挡”本身也应触发，要明确写成风险条件，或反向排除安全状态：

```text
思维条件3: 内容理解 / 正向思维1 / 人员手部被遮挡、不可见，且疑似正在携带或操作物品
思维条件4: 内容理解 / 反向思维1 / 双手清晰可见且未拿任何物品
```

## 8. 小物体混淆

香烟、鱼竿、手机、小工具都可能很小。用“手/嘴/工具/动作/点燃或使用状态”组合判断，并写常见误报。

```text
思维条件1: 内容理解 / 正向思维1 / 是否嘴里有烟
思维条件2: 内容理解 / 正向思维1 / 是否手中有烟
思维条件3: 内容理解 / 正向思维1 / 是否点着了
思维条件4: 内容理解 / 正向思维1 / 是否手里夹着烟
思维条件5: 内容理解 / 反向思维1 / 是否误识别为棒棒糖
```

## 9. 人员身份、年龄、性别、服饰

先用 `目标理解 / 人` 锚定人员，再用内容/深度内容理解判断身份特征。

身份类不要只写“指导员/老人/儿童/陪酒女”等标签，要拆成可见证据：

```text
脸
正脸
完整身体
年龄
性别
制服
袖章
反光背心
马甲
特殊服饰
```

示例：

```text
思维条件1: 目标理解 / 通用目标理解 / 人 / 大于 / 0
思维条件2: 内容理解 / 正向思维1 / 图中是否可以看到正脸
思维条件3: 内容理解 / 正向思维1 / 图中人是否为儿童
思维条件4: 内容理解 / 反向思维1 / 图中人是否为成年人
```

看不清脸、身体或服饰时，不要过度相信年龄/性别/身份判断。

## 10. 人员身份排除

识别指导员、工作人员等角色时，要排除相似职业或相似穿着。

```text
思维条件1: 目标理解 / 通用目标理解 / 人 / 大于 / 0
思维条件2: 深度内容理解 / 正向深度思维1 / 图中人是否穿着反光背心
思维条件3: 深度内容理解 / 正向深度思维1 / 图中人是否穿着马甲
思维条件4: 深度内容理解 / 反向深度思维1 / 图中人是否是送外卖或者送快递的
```

## 11. 容器状态

垃圾桶满溢、未盖盖等任务，写成“容器目标 + 状态证据 + 正常状态反向排除”。

满溢：

```text
思维条件1: 目标理解 / 多模态目标理解 / garbage bins / 大于 / 0
思维条件2: 深度内容理解 / 正向深度思维1 / 图中垃圾桶本身是否有明显的溢出
思维条件3: 深度内容理解 / 正向深度思维1 / 图中垃圾桶的垃圾堆积超出了桶的边缘
思维条件4: 深度内容理解 / 反向深度思维1 / 图中垃圾是否相对规整且明显的在垃圾桶内
```

未盖盖：

```text
思维条件1: 目标理解 / 多模态目标理解 / garbage bins / 大于 / 0
思维条件2: 深度内容理解 / 正向深度思维1 / 图中垃圾桶盖翘起、敞开、半开，桶口明显外露
思维条件3: 深度内容理解 / 反向深度思维1 / 图中垃圾桶盖完全闭合，桶口不可见
```

## 12. 缺失和未穿戴

“未戴安全帽”“未穿反光衣”等缺失类任务，本质是“有人 + 没有合规装备”。先找人，再用反向思维排除合规状态。

```text
思维条件1: 目标理解 / 通用目标理解 / 人 / 大于 / 0
思维条件2: 深度内容理解 / 反向深度思维1 / 图中人是否佩戴安全帽
思维条件3: 深度内容理解 / 反向深度思维1 / 图中是否存在白色、红色或蓝色安全帽
```

## 13. 高风险行为

暴力、打架、严重攻击等高风险行为，可以用多条兼容的正向描述提高精度。

```text
思维条件1: 内容理解 / 正向思维1 / 图中是否存在严重暴力攻击行为
思维条件2: 内容理解 / 正向思维1 / 图中是否发生严重打架斗殴行为
思维条件3: 目标理解 / 通用目标理解 / 人 / 大于 / 0
思维条件4: 内容理解 / 正向思维1 / 图中是否存在明显的肢体攻击动作
```

注意：不添加逻辑行时，这些正向描述会被平台按 `AND` 组合，必须能同时成立。若只是不同候选行为，例如“推搡或踢打或追逐”，要用 `逻辑理解 / 或者`。

## 14. 复杂场景判断

交通事故、花屏、异常画面这类全局场景，优先用内容/深度内容理解，不要强行拆成目标。

```text
思维条件1: 内容理解 / 正向思维1 / 图中主干道路是否发生了明显交通事故
思维条件2: 内容理解 / 反向思维1 / 图中主干道路未发生交通事故
思维条件3: 深度内容理解 / 正向深度思维1 / 图中主干道路是否发生了明显交通事故
思维条件4: 深度内容理解 / 反向深度思维1 / 图中主干道路未发生交通事故
思维条件5: 深度内容理解 / 反向深度思维1 / 画面存在明显彩色斑点、条纹或像素花屏现象
思维条件6: 内容理解 / 反向思维1 / 图中画面发生断层
```

误报来源如果是画质问题、花屏、断层，要单独写反向排除。
