# 平台组件和字段

## 目录

- `内容理解`: 正向/反向思维组件和 parsingId
- `深度内容理解`: 深度思维组件和 parsingId
- `目标理解`: 通用目标、多模态目标、套框规则
- `文字理解`: OCR 组件
- `逻辑理解`: OR 和其他逻辑控制项
- `执行顺序`: 条件逐层过滤
- `启用区域框`: 检测区域含义
- `解析模式补充`: 延伸比例控件

## 内容理解

常用组件：

```text
正向思维1
正向思维2
正向思维20
反向思维1
反向思维2
反向思维20
```

用法：

- `正向思维`：要识别、要出现、要满足的内容。
- `正向思维1`：初版能力；填写内容就是完整 prompt，平台基本按输入内容直接理解。
- `正向思维2`：调优迭代版；内部已有固定提示词，填写内容作为变量传入。
- `反向思维`：主要用于调试误报。不要默认添加；先用正向主证据跑，确认某类误报反复出现后，再针对性补一条。

已从提交 curl 确认的 `parsingId`：

| 组件 | parsingId |
| --- | --- |
| 正向思维1 | 1 |
| 正向思维2 | 11 |
| 正向思维20 | 21 |
| 反向思维1 | 2 |
| 反向思维2 | 12 |
| 反向思维20 | 22 |

选择建议：

- 默认先用 `正向思维1`。
- 当同类需求已经验证 `正向思维2` 更稳，或需要平台内置调优提示词参与判断时，再用 `正向思维2`。
- 不要在同一编排里无理由混用 `正向思维1` 和 `正向思维2`。

示例：

```text
算法: 识别小女孩
思维条件1: 内容理解 / 正向思维1 / 女孩
思维条件2: 内容理解 / 正向思维1 / 小孩
思维条件3: 内容理解 / 反向思维1 / 成年男人
```

## 目标理解

用于识别具体物体，分两类：

```text
通用目标理解
多模态目标理解
```

只有加了 `目标理解` 下面的组件，平台才会在检测出来的画面里给物体套框。`内容理解`、`深度内容理解` 可以判断语义、状态、关系，但不会单独给物体套框。

### 通用目标理解

目标在内置列表里时使用。已从平台下拉框确认的通用目标包括：

```text
人
机动车辆
汽车
卡车
摩托车/电动车
公交车
火车
船
红绿灯
狗
猫
手包
行李箱
背包
屏幕
笔记本电脑
椅子
键盘
电话
盆栽植物
瓶子
杯子
碗
床
伞
香蕉
```

不在这个列表里的目标，优先用 `多模态目标理解`，不要硬套通用目标。

格式：

```text
目标理解 / 通用目标理解 / [内置目标] / 大于|小于|等于 / [置信度数字]
```

最后的数字是置信度，不是目标数量。

### 多模态目标理解

通用目标没有该目标时使用。目标文本尽量写英文。

```text
垃圾桶 -> garbage bin / garbage bins
安全帽 -> helmet
叉车 -> forklift
烟雾 -> smoke
```

格式：

```text
目标理解 / 多模态目标理解 / garbage bins / 大于 / 0
```

除非已验证平台支持中文，否则多模态目标字段不要写中文。

## 文字理解

只在需求明确是可见文字时使用：

```text
识别屏幕上的“故障”
识别标牌文字
识别车牌/编号
识别告警文字
```

已知平台值：

```text
文字理解 / OCR -> parsingId: ocr
```

格式：

```text
文字理解 / OCR / [要识别的文字或规则]
```

如果平台规则值是固定开关，可直接按页面值填写，例如：

```text
思维条件1: 文字理解 / OCR / 1
```

如果 OCR 需求也能被语义理解覆盖，保存前先确认。

## 逻辑理解

`逻辑理解` 用于条件块之间的逻辑连接，不用于普通检测。

关键规则：

```text
不添加任何逻辑理解行时，平台会把这些思维条件块默认按 AND 组合。
这不是要求每个编排都必须 AND。
共同成立才预警 -> 不加逻辑行
任一候选成立就预警 -> 显式添加 逻辑理解 / 或者
```

已知逻辑选项：

```text
或者
前置条件结束
输出分支预警
输出其他预警
预警结果反转
预警内容输出
预警结果数量
预警框内目标数量
```

OR 示例：

```text
思维条件1: 内容理解 / 正向思维1 / 出现明火
思维条件2: 逻辑理解 / 或者
思维条件3: 内容理解 / 正向思维1 / 出现浓烟
```

没有逻辑行时，不要假设每行可以独立触发。

## 执行顺序

整体算法按从上到下的顺序执行，逐层过滤。

只有上面的条件满足后，才会继续执行下面的算法或条件。把便宜、稳定、宽泛的条件放前面，把细节判断、排除项、调优条件放后面。

## 启用区域框

`启用区域框` 表示不使用整个画幅作为检测范围，而是只取画面中的一部分区域进行检测。

涉及固定点位、禁区、设备区域、门口、桶边、道路局部等场景时可以开启；如果业务要求全画面检测，保持关闭或按平台默认。
